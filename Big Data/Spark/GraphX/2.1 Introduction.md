# Apache Spark GraphX: Advanced Analytics & PageRank Implementation

This guide outlines the complete technical implementation of a distributed, property-driven **Academic Collaboration Network** using the Spark GraphX API, concluding with structural graph analytics via the PageRank algorithm.

## 1. Network Topology & Use Case Schema

Our network models complex multi-entity academic relationships (Students, Postdocs, Professors) and their directional dependencies (Advisors, Co-authors, Principal Investigators).

### The Data Contract

* **Vertex Data Type (`VD`):** `(String, String)` $\rightarrow$ `(Name, Academic Role)`
* **Edge Data Type (`ED`):** `String` $\rightarrow$ `Relationship Label (e.g., "collab", "advisor")`

---

## 2. Production Code Implementation (Interactive Shell Ready)

Since interactive environments (like the Spark Shell, Databricks, or configured notebooks) automatically expose the `SparkContext` as `sc`, we omit the boilerplate configurations to prevent singleton conflicts.

```scala
import org.apache.spark.graphx._
import org.apache.spark.rdd.RDD

// -------------------------------------------------------------------------
// 1. VERTEX SCHEMA DESIGN (ID, (Name, Role))
// -------------------------------------------------------------------------
// Explicitly enforcing VertexId (Long) for stable data mapping
val vertexArray: Array[(VertexId, (String, String))] = Array(
  (3L, ("rxin", "student")),
  (7L, ("jgonzal", "postdoc")),
  (5L, ("franklin", "prof")),
  (2L, ("istoica", "prof"))
)
val vertexRDD: RDD[(VertexId, (String, String))] = sc.parallelize(vertexArray)

// -------------------------------------------------------------------------
// 2. EDGE SCHEMA DESIGN (SrcId, DstId, Relationship)
// -------------------------------------------------------------------------
val edgeArray: Array[Edge[String]] = Array(
  Edge(3L, 7L, "collab"),
  Edge(5L, 3L, "advisor"),
  Edge(2L, 5L, "colleague"),
  Edge(5L, 7L, "pi")
)
val edgeRDD: RDD[Edge[String]] = sc.parallelize(edgeArray)

// -------------------------------------------------------------------------
// 3. ROBUST FALLBACK STATE
// -------------------------------------------------------------------------
// Prevents runtime NullPointerExceptions if data contains dangling edges
val defaultUser = ("john doe", "missing")

// -------------------------------------------------------------------------
// 4. GRAPH INSTANTIATION
// -------------------------------------------------------------------------
val graph: Graph[(String, String), String] = Graph(vertexRDD, edgeRDD, defaultUser)

```

## 3. High-Performance Predicate Filtering

GraphX predicates should leverage pattern matching to unpack nested properties cleanly without accessing array indexes directly.

### Advanced Vertex Filtering

When filtering structural elements, pattern matching strips out the structural tracking components safely:

```scala
// Isolate specific institutional nodes (Postdocs)
val postdocCount = graph.vertices.filter { 
  case (id, (name, role)) => role == "postdoc" 
}.count()

println(s"Active Postdoc Nodes: $postdocCount")

```

### Directional Edge Filtering

Filtering based on topological layout (e.g., identifying recursive patterns or specific directional relationships):

```scala
// Filter edges where the Source ID is higher than the Destination ID
val directionalEdges = graph.edges.filter { 
  case Edge(srcId, dstId, relationship) => srcId > dstId 
}.count()

```

## 4. Measuring Node Influence via PageRank

The `.pageRank(tolerance)` method is an iterative graph algorithm that measures the structural importance of each vertex based on the quantity and quality of incoming links.

### Execution Mechanics

```scala
// Run PageRank with a strict convergence tolerance threshold
val dynamicRankGraph = graph.pageRank(0.0001)
val rankVertices: VertexRDD[Double] = dynamicRankGraph.vertices

```

### Mapping Results to Profiles

Because `pageRank` returns a plain `VertexRDD[Double]`, we join it back to the original graph properties to output human-readable insights:

```scala
// Inner join the numerical ranks with the profile labels
val highValueNodes = graph.vertices.join(rankVertices)

highValueNodes.collect().foreach { 
  case (id, ((name, role), rank)) =>
    println(f"Profile: $name%-10s | Role: $role%-10s | Influence Score: $rank%.4f")
}

```

### Analysis of Sample Output

* **`jgonzal` (Rank: ~1.66) $\rightarrow$ Most Influential:** Receives multiple incoming high-weight operational structural edges (`rxin` $\rightarrow$ `jgonzal` and `franklin` $\rightarrow$ `jgonzal`).
* **`istoica` (Rank: ~0.50) $\rightarrow$ Latent Base Rank:** Acts purely as a root source node with zero incoming paths, establishing the structural baseline value.

## 5. Architectural Performance Cheat Sheet

* **Immutability Policy:** Transforming a graph via filtering (`.subgraph()`) or analytics (`.pageRank()`) creates a *new logical view*. It shares structural tables in memory to optimize memory utilization.
* **Tolerance vs. Interations:** Passing a `Double` parameter (e.g., `0.0001`) runs **Dynamic PageRank**, which stops automatically once scores stabilize below that error gap. Calling `.staticPageRank(int)` forces the system to run exactly $N$ iterations regardless of early convergence.
* **Garbage Collection Warning:** Always call `graph.persist()` before running iterative analytical steps like PageRank to avoid re-reading raw files during downstream shuffles.
